# Handoff Shape Evaluation Note

## Candidate Generic Handoff Shapes

| Candidate handoff shape | Assessment | Why |
| --- | --- | --- |
| `content blocks` | reusable now | Already matches Diego's generic content-object output direction and can be projected by multiple artifact-first consumers. |
| `sectioned long-form draft` | reusable now | A plan plus sectioned draft is a stable drafting handoff for longer-form consumers without forcing one render target. |
| `outline + expansion bundle` | promising but premature | The shape is plausible, but Diego has not yet defined a settled generic bundle contract beyond current drafting and structure-expansion notes. |
| `source-conditioned draft package` | reusable now | Topic, source scope, plan, draft, citations, and revision truth form a reusable generation-side package. |
| `structured item/question generation package` | promising but premature | Reuse potential exists, but Diego still lacks a generic item object with grounding, revision, and answer-boundary semantics. |
| `structure-aware concept expansion package` | promising but premature | The semantic direction is real, but the output contract should be clarified before it is treated as a stable consumer handoff. |

## Main Reading

The smallest reusable downstream handoff direction today is:
- lightweight generic content objects
- sectioned long-form draft structure
- grounded drafting inputs and revision truth

These shapes appear reusable across more than one artifact-first consumer without turning Diego into product ontology.

The main thing that should remain consumer-side is:
- projection into markdown or another presentation format
- artifact-specific formatting policy
- final assembly into host-owned formal artifacts

# Generic Primitive Boundary Note

## What Must Not Enter Diego

Diego must stay capability-shaped.

The following concerns must remain outside Diego:
- product-mode naming
- shell glue and workbench routing
- selection anchor mapping
- graph editing semantics
- local preview truth
- export or compile ownership for non-PPT content
- formal artifact truth
- runtime interaction semantics
- artifact library return policy
- host workflow state
- host-specific refine transport behavior

Boundary rule:
- if a capability cannot be described without a specific host workflow, editor surface, or product label, it does not belong in Diego yet.

Diego should own:
- generic generation contracts
- grounded drafting and bounded revision
- explicit lifecycle and failure truth
- generic content outputs that downstream shells can project or render
